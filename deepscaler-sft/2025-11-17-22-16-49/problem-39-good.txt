To solve this problem, we can model it using a recursive approach because the movement of the checker has specific constraints. The checker can move either to the adjacent cell or skip one cell.

To calculate the number of ways to move 10 cells or 11 cells, we can define a function that will compute this recursively. We'll start by defining a function that will store the number of ways to reach each cell up to 11 cells away.

Let's denote \( f(n) \) as the number of ways to move onto the \( n \)-th cell. To reach the \( n \)-th cell, the checker can either come from the \( (n-1) \)-th cell (by moving to the adjacent cell) or from the \( (n-2) \)-th cell (by skipping one cell). Therefore, the recurrence relation can be written as:
\[ f(n) = f(n-1) + f(n-2) \]
where:
- \( f(0) = 1 \) (there is one way to be at the starting cell, which is doing nothing)
- \( f(1) = 1 \) (there is one way to move to the first cell, which is a single move from 0 to 1)

Using this recurrence relation, we can iteratively calculate the values for \( f(2) \) through \( f(11) \).

Let's implement this in Python.
```python
def count_ways(n):
    # Base cases
    if n == 0:
        return 1
    if n == 1:
        return 1
    
    # Create an array to store the number of ways to reach each cell up to n
    ways = [0] * (n + 1)
    ways[0] = 1
    ways[1] = 1
    
    # Fill in the ways array using the recurrence relation f(n) = f(n-1) + f(n-2)
    for i in range(2, n + 1):
        ways[i] = ways[i - 1] + ways[i - 2]
    
    return ways[n]

# Calculate the number of ways to move 10 cells and 11 cells
ways_10_cells = count_ways(10)
ways_11_cells = count_ways(11)

print((ways_10_cells, ways_11_cells))
```
